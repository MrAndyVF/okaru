Hooks are advanced automation entries under `[hooks]` in the OKARU config stack. For hand-written hooks, put them in any `*.toml` file under `~/.config/okaru/`. They run extra commands when specific OKARU events happen.

Each event is a shell command string or an array of shell command strings that run in order. Use `okaru msg ...` when a hook needs to call OKARU IPC.

Hooks do not replace OKARU's built-in behavior. For example, external or IPC-initiated Wi-Fi, Bluetooth, and power profile changes show an OSD. `notify-send` can be useful while testing that a hook fires, but it is not required for OKARU's own feedback.

| Key                                        | When it fires                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `started`                                  | Once after OKARU finishes startup (IPC ready).                                                                                                                                                                                                                                                                                                           |
| `wallpaper_changed`                        | After a persisted wallpaper path change is applied. Sets `OKARU_WALLPAPER_PATH` and `OKARU_WALLPAPER_CONNECTOR` (for example `DP-1`; empty when the change is not tied to a live connector).                                                                                                                                                          |
| `colors_changed`                           | After the theme palette is resolved and terminal templates are updated.                                                                                                                                                                                                                                                                                     |
| `theme_mode_changed`                       | After theme templates are applied, when the resolved [`[theme].mode`](/okaru/theming/#mode) changes between `light` and `dark`. This is the app-facing mode, so it ignores [`shell_mode`](/okaru/theming/#shell_mode). Sets `OKARU_THEME_MODE`, `OKARU_THEME_MODE_PREVIOUS`, and `OKARU_THEME_MODE_CONFIGURED` (`dark`, `light`, or `auto`). |
| `session_locked`                           | When the compositor confirms the session lock.                                                                                                                                                                                                                                                                                                              |
| `session_unlocked`                         | When the session leaves the locked state.                                                                                                                                                                                                                                                                                                                   |
| `logging_out`                              | Immediately before the session panel runs the logout sequence.                                                                                                                                                                                                                                                                                              |
| `rebooting`                                | Immediately before the session panel runs reboot or reboot to UEFI.                                                                                                                                                                                                                                                                                         |
| `shutting_down`                            | Immediately before the session panel runs shutdown.                                                                                                                                                                                                                                                                                                         |
| `wifi_enabled` / `wifi_disabled`           | When NetworkManager's Wi-Fi radio toggles (not on first snapshot, and not when NetworkManager stops or starts).                                                                                                                                                                                                                                             |
| `bluetooth_enabled` / `bluetooth_disabled` | When the default adapter's powered state toggles (not on first snapshot).                                                                                                                                                                                                                                                                                   |
| `battery_charging`                         | When the battery enters charging after the previous tracked battery hook state was not charging. Intermediate UPower states do not retrigger it.                                                                                                                                                                                                            |
| `battery_discharging`                      | When the battery enters discharging after the previous tracked battery hook state was not discharging. Intermediate UPower states do not retrigger it.                                                                                                                                                                                                      |
| `battery_plugged`                          | When the battery enters fully charged or pending charge after the previous tracked battery hook state was not plugged. Intermediate UPower states do not retrigger it.                                                                                                                                                                                      |
| `battery_percentage_changed`               | When the normalized whole battery percentage changes. Sets `OKARU_BATTERY_STATE` (`charging`, `discharging`, `empty`, `fully_charged`, `pending_charge`, `pending_discharge`, or `unknown`) and `OKARU_BATTERY_PERCENT`.                                                                                                                              |
| `power_profile_changed`                    | When the active UPower power profile changes (for example `performance`, `balanced`, or `power-saver`). Sets `OKARU_POWER_PROFILE`, `OKARU_POWER_PROFILE_PREVIOUS`, and `OKARU_POWER_PROFILE_ORIGIN` (`okaru` or `external`).                                                                                                                   |

## Battery hooks

Battery hook values are exposed as environment variables, not positional arguments. For example:

```toml
[hooks]
battery_percentage_changed = "notify-send 'Battery' \"$OKARU_BATTERY_PERCENT% ($OKARU_BATTERY_STATE)\""
```

To run an action only when the battery is discharging and has just crossed below a threshold, store the previous percentage in a small script:

```toml
[hooks]
battery_percentage_changed = "OKARU_BATTERY_THRESHOLD=20 ~/.config/okaru/hooks/battery-threshold.sh"
```

```bash title="~/.config/okaru/hooks/battery-threshold.sh"
#!/usr/bin/env bash
set -euo pipefail

# Use the threshold from the hook command, or fall back to 20%.
threshold="${OKARU_BATTERY_THRESHOLD:-20}"

# Keep a tiny state file so the script can compare this event with the last one.
state_dir="${XDG_STATE_HOME:-$HOME/.local/state}/okaru"
state_file="$state_dir/battery-percent"

# OKARU provides these values whenever battery_percentage_changed fires.
percent="${OKARU_BATTERY_PERCENT:-}"
battery_state="${OKARU_BATTERY_STATE:-unknown}"

# Ignore the event if the percentage is missing or not a whole number.
[[ "$percent" =~ ^[0-9]+$ ]] || exit 0

mkdir -p "$state_dir"

# Read the previous percentage, then save the current percentage for next time.
previous=""
[[ -r "$state_file" ]] && previous="$(<"$state_file")"
printf '%s\n' "$percent" > "$state_file"

# Only warn while discharging, and only after we have a previous value to compare.
[[ "$battery_state" == "discharging" ]] || exit 0
[[ "$previous" =~ ^[0-9]+$ ]] || exit 0

# Fire once when crossing below the threshold, not every time the battery changes below it.
if (( previous >= threshold && percent < threshold )); then
  notify-send -u critical "Battery low" "Battery is ${percent}%."
  # Or run any other command, for example:
  # systemctl --user start low-battery.target
fi
```

## Wallpaper hooks

Wallpaper hook values are exposed as environment variables, not positional arguments. `OKARU_WALLPAPER_PATH` is the applied path, and `OKARU_WALLPAPER_CONNECTOR` is the output connector for that wallpaper change. When multiple outputs change, the hook runs once per changed connector.

```toml
[hooks]
wallpaper_changed = "logger -t okaru-hooks \"Wallpaper on $OKARU_WALLPAPER_CONNECTOR: $OKARU_WALLPAPER_PATH\""
```

## Examples

```toml
[hooks]
# Start a user unit after OKARU IPC is ready.
started = "systemctl --user start okaru-ready.target"

# Log wallpaper changes with the connector-specific payload.
wallpaper_changed = "logger -t okaru-hooks \"wallpaper: $OKARU_WALLPAPER_CONNECTOR $OKARU_WALLPAPER_PATH\""
colors_changed = [
  "systemctl --user reload foot-server.service",
  "logger -t okaru-hooks 'palette colors changed'",
]
theme_mode_changed = "logger -t okaru-hooks \"mode: $OKARU_THEME_MODE\""

# Combine normal shell commands with OKARU IPC commands.
session_locked = [
  "playerctl pause",
  "okaru msg bar-hide",
]
session_unlocked = [
  "okaru msg bar-show",
  "okaru msg dpms-on && notify-send 'Session resumed'",
]

logging_out   = "logger -t okaru-hooks 'logout requested'"
rebooting     = "systemctl --user stop backup-sync.service"
shutting_down = "systemctl --user stop backup-sync.service"

# External or IPC-initiated Wi-Fi, Bluetooth, and power profile changes use OSD.
# Use hooks only for extra side effects.
wifi_enabled  = "logger -t okaru-hooks 'Wi-Fi radio enabled'"
wifi_disabled = "logger -t okaru-hooks 'Wi-Fi radio disabled'"

bluetooth_enabled  = "logger -t okaru-hooks 'Bluetooth powered on'"
bluetooth_disabled = "logger -t okaru-hooks 'Bluetooth powered off'"

battery_charging           = "logger -t okaru-hooks 'Battery charging'"
battery_discharging        = "logger -t okaru-hooks 'Battery discharging'"
battery_plugged            = "logger -t okaru-hooks 'Battery plugged'"
battery_percentage_changed = "logger -t okaru-hooks \"Battery: $OKARU_BATTERY_STATE $OKARU_BATTERY_PERCENT%\""
power_profile_changed   = "logger -t okaru-hooks \"Power profile: $OKARU_POWER_PROFILE_PREVIOUS -> $OKARU_POWER_PROFILE ($OKARU_POWER_PROFILE_ORIGIN)\""

# Quick test while developing a hook; not needed for OKARU's own notifications.
# started = "notify-send 'OKARU hook' 'started fired'"
```
